How to Run the server and client[edit]

Using Windows Powershell/CMD:[edit]

open the frontier-station-14 folder, then right click inside it without selecting anything in particular, then click "open in terminal", you might need to press the show more options button.

once you do type in dotnet run -c Release --project Content.Server into the terminal, then wait until "ready" pops up, once it does, open the game launcher from steam, then click on "Direct connect to server" then type in "localhost", you've successfully entered the lobby window! read the rest of the instructions in the below section


Using an IDE like VS code:[edit]

open the frontier-station-14 folder then right click inside it without selecting anything in particular, you might need to press the show more options button but you'll see a "open with (IDE name)" as one of the options, once you do that you'll be able to edit the game files much easier,

and for our purposes you'll be able to run the server/client build in release mode much easier, just go to the run and debug tab (might be different name for your IDE) and look for Server/Client (release).

once the IDE finishes loading it you'll get a window with a username field, server adress, direct connect, options, quit, and changelog, make sure the server adress is "localhost" and press direct connect, you've successfully entered the lobby window! read the rest of the instructions in the below section


what to do from the lobby window:[edit]

join as observer, once you load in you'll see 3 new admin menus, you'll use the first 2, open the "admin menu" on the "admin tab" then click on admin ghost, this is essential as it's what allows you to be able to interact with a uninitialized map.

once you do you'll need to type in mapping (mapid) /[path to ship file] where mapid is any number that isn't already used and the / is the path to the ship file (you can use 100 if you're unsure, it's never used). /Maps/_NF/Shuttles/ for ships already added to frontier, and for ships you're saving into the frontier-station-14/bin/Content.Server/data path, if you don't add any ship file, then you'll be in a blank space with nothing in it!


List of ESSENTIAL Commands:[edit]

mapping (mapid) [/path/to/shuttle][edit]

creates a blank uninitialized map, makes you an admin ghost, then teleports you to it. you can put in the path to shuttle if you want or not, if it's blank then the map will be empty and you can just use the loadgrid command to load a ship in

Examples:

  • mapping 100 : it first makes you an admin ghost if you aren't already, then it (sometimes it's rather glitchy and doesn't) runs the mappingclientsidesetup command, then teleports you to map 100
  • mapping 100 /Maps/_NF/Shuttles/surveyor.yml : it first makes you an admin ghost if you aren't already, then it (sometimes it's rather glitchy and doesn't) runs the mappingclientsidesetup command, then teleports you to map 100 then it loads the surveyor shuttle into the map
  • mapping 100 /test.yml : it first makes you an admin ghost if you aren't already, then it (sometimes it's rather glitchy and doesn't) runs the mappingclientsidesetup command, then teleports you to map 100 then loads the ship using the file test.yml from frontier-station-14/bin/Content.Server/data into the map


loadgrid (mapid) /path/to/shuttle x-position y-position[edit]

allows you to load a grid onto any map, even an uninitialized mapping map! but without going through the shipyard console system it'll end up without the drive/cruise/park settings shuttles have

/Maps/_NF/Shuttles/ for ships already added to frontier, and for ships you're saving they're in frontier-station-14/bin/Content.Server/data,

Examples:

  • loadgrid 100 /Maps/_NF/Shuttles/surveyor.yml : loads the surveyor shuttle into the map 100, if the map doesn't exist it makes it then loads the shuttle
  • loadgrid 100 /test.yml : loads the ship using the file test.yml from frontier-station-14/bin/Content.Server/data into the map 100, if the map doesn't exist it makes it then loads the shuttle


purchaseshuttle (stationid) /path/to/shuttle (ship atmosphere)[edit]

spawns a ship at the specified station, it doesn't use the standard grid id, so you'll have to search with the suggested ones, it usually has the station your on as the first suggestion.

you can also open the admin menu, go to objects, then switch to Stations instead of grids to find the station ID

startround[edit]

this makes the game load in ASAP, bypassing the 3 minute wait time.


mappingclientsidesetup[edit]

this command adds a bunch of tiles/items to your actions bar, the main thing you'll use it for is deleting entities


aghost[edit]

this command turns you into an admin ghost without having to go through the admin menu


physics com[edit]

it shows the ships Centre Of Mass (com) as a large orange ball, if you see more than one then that means your Grid has split, due to how buggy mapping tools are just ctrl clicking out plating has a high chance of making some tiles that aren't connected to the main grid, please be sure to keep it on whenever you're modifying the ship's structure even a little bit

tp x y (mapid)[edit]

this command allows you to teleport into any x and y coordinate into any map, say you've teleported back to FO's mapid which is always 1 to buy a ship to look at as reference, to teleport back to your grid you just add it's mapid rather than FO's


colornetwork (networkid) Pipe (#hexcode)[edit]

this command colors a pipe network, it needs to be Pipe with a capital P at the begining otherwise it won't work to find the network id, you just right click a pipe, the number you see is the network id!

it's included with other pins in the mapping general discord channel but the main colors are:

  1. #990000 for scrubber networks
  2. #0055cc for air distribution pipes
  3. #9955cc for auxilery gas networks

variantize (gridid)[edit]

this command adds the different variaties of tiles and adds garbage to the ship when it spawns, all ships are required to run this command before adding to the game


fixgridatmos (gridid)[edit]

this command fixes/adds air to the tiles of the ship , run it when you're finishing up a build and everytime you edit the ship's walls/shape


savegrid (gridid) /(shipname).yml[edit]

this one saves the ship grid into the frontier-station-14\bin\Content.Server\data path as a file, you'll need to appemd .yml to the end of the ship's name to save as a yml file


appraisegrid (gridid)[edit]

this one allows you to know how much is worth, you should only run it on a initialized grid!


gridtc (gridid)[edit]

this one counts all the tiles in the grid, is used for ship size classificiation


mapinit (mapid)[edit]

initializes the map whose id you used, do NOT use it before you save your ship, but it'd allow you to test the ship in an empty map, alternatively you can use the next command to test it in the Frontier map


nodevis[edit]

shows you the connections between the different Cables or Pipes, only works if you see them using the "show subfloor" in the admin menu

Ship Submition Guidelines[edit]

these can be found on the frontier station site, you're meant to give it a very thorough read; so you're not forced to redo the shuttle with them in mind, as all ships follow them, you do have some leeway with some of them, but you'd need to ask before hand to make sure


Setting up a Ship's ID[edit]

Before you can get the ship into the shipyard console, you'll need to add a ship specific ID to refer to the ship within the files, you'll need to use these 2 following commands


vv (gridid)[edit]

this allows you to edit the components of the ship's grid, the only thing you need to do is go to the server components tab, press "Add Component" then search for BecomesStation, once you do that, write out the next command to EDIT the ship's name!


vvwrite /entity/(gridid)/BecomesStation/Id "(shipname)"[edit]

this allows you to change the grid's ID properly, all you need to do is replace the gridid with the ship's, and the shipname with the ship's name that will be used as it's ID


How to add a shuttle to the shipyard console[edit]

and if you want to figure out how to add all the needed files for it to appear in the shipyard console, then i'd recommend reading

This PR: https://github.com/new-frontiers-14/frontier-station-14/pull/4294

as reference to all the files you need to change/add, just ignore anything relating to posters as that's to allow a company logo to show within the guidebook page.

but if you want the bare minimum set up, then all you need to do is add the shuttle's .yml file in frontier-station-14\Resources\Maps\_NF\Shuttles -or inside a folder within this file for expedition/staff shuttles-

and add a file in frontier-station-14\Resources\Prototypes\_NF\Shipyard, you can open one for a shuttle of a similar archetype and use it as a template, while having the guidebookPage: Null, this will make it purchusable without a guidebook entry.

keep in mind, you need to have the class and engine match the ingame ones to the letter, otherwise the ship won't show up at all

Common Mistakes[edit]

Building the ship's front not facing north[edit]

this one happens because people assume the ship's front is asigned by the ship's console, this isn't true however, it is the grid's north that should be the ship's front, as otherwise you'd have to rotate the ship console, which in turn rotates the camera view and the controls, you don't want to redo the whole ship after you make it!


Not using the decal menu for decals[edit]

the reason we use the specific admin decal menu rather than the magic spray painter, is that the decal menu can specifiy whether they can be cleaned away or not, while the magic spray painter's decals are all cleanable, don't want all your decals to be sweeped away!


Using the rotation field for different decal orientations[edit]

the reason why different orientations are defined rather than expecting you to use the rotation field, is because of 2 reasons:

  1. it's way faster than typing in 0 90 180 manually every time
  2. the decals are made to align only using the different decals, and they don't align with manual rotations


Not testing the ship before PR[edit]

running a couple test flights helps illuminate MANY mistakes you've missed! you're never trully done unless you do a run of the main task your ship was designed for


Not using ctrl+f to find and replace all the old shuttle's name[edit]

when you're copying over the shipyard entry yml folder in frontier-station-14\Resources\Prototypes\_NF\Shipyard be sure to use ctrl+f to find all the mentions of the old shuttle and replace them, a lot of people miss at least one mention and end up with problems while testing their shuttle, an example: Our Clown shipwright Blundibus struggled too

Not linking the air alarms to firelocks/vents/scrubbers[edit]

air alarms don't magically know what the air in the room they're in is like, they check the devices they're linked to, and close the firelocks when a warning thresholds hit


Running in Debug Mode[edit]

running in debug mode is only really intended for debuging entities and other objects that you work on outside the game this is mostly because Debug mode ensures that whenever any error shows up; no matter how small, it will end up crashing the entire server, and mapping tools aren't stable enough to not give out any error messages, and since mapping is done ingame via ingame tools, having it crash on you while you're mapping is a good way to waste your time!


Using the shipyard consoles ship price[edit]

the PROPER way to see a ship's value is using the appraisegrid command on a newly bought ship, because the shipyard console only shows 95% of the true shuttle's value while appraisegrid shows the true value as is.


Using appraisegrid on an uninitialized grid[edit]

this results in a far lower value as after initializing a lot of value is added from the machines/lockers/fills/etc

Deleting your admin ghost[edit]

did you know you can delete yourself? upon doing so you'll become a regular ghost, and as mentioned above only admin ghosts get simulated in uninitialized maps, that means you need to readmin ghost yourself

thankfully this is easy, all you need to do is teleport to an object within an initialized map using the "objects" tab in the admin menu ;Frontier Outpost works well for this, and then readmin ghost yourself using the admin menu again! you can now safely go back to the map you were building on using the tp command listed above


Not using signal switches instead of signal buttons[edit]

the regular button only has one port, which activates on a press, meaning it can only send one type of signal, this can be remedied by toggle ports in the things you're linking it with but some machines like conveyors don't have such a port......

that's where signal switches come in! they have 3 ports!

  1. on: sends a signal when it's turned on
  2. off: sends a signal when it's turned off
  3. Status: sends a signal when it switches modes

the use of signal switches can be seen within the dragoon and the surveyor, they're used for conveyors in those!


Not using all 3 pipe layers[edit]

if you use the entity spawner menu to select pipes you'll notice you can place them in all 3 layers as opposed to the pipes givven by mappingclientsidesetup, be sure to use all 3 pipe layers as otherwise the piping will be messy, keep in mind you're allowed to screwdriver vents and scrubers to lead directly into these different layer pipes


Picking up and droping items to reposition them[edit]

this isn't ideal, as it saves the info about the deleted entities, so delete the entity then place another down to reposition


using the (ghost only warp point) instead of Warp point[edit]

the warp point (ship) automatically includes the ship info, while ghost only warp point doesn't.

Common Questions[edit]

Can i place Items in a square?[edit]

Yes, ctrl click for a square, or shift click for a line. (note this can be glitchy and spawn tiles as seperate grids, ALWAYS use physics com when placing tiles)

What map is FO in?[edit]

in map 1

How does the grid/map system work?[edit]

i'll keep the explanation simple for the purposes of knowing enough to map: when you save a shuttle, you save it as a grid, when you use the shipyard console to purchase the ship, it turns the ship from a grid, to a map.

what that means is that if you're working on map 100, and saved the ship, you can just go to map 101 and loadgrid the saved ship, the ship isn't tied to a specific map.

ship files are stored as .yml files, so when you want to save your ship using the savegrid command, be sure to append .yml to the end of the ship's name!

Where are the ship files stored?[edit]

the ones you save yourself are stored at frontier-station-14\bin\Content.Server\data while the ones already within the game are in frontier-station-14\Resources\Maps\_NF\Shuttles


How to add more than one Object on a wall/tile?[edit]

  1. Place the Object down
  2. Right click and select View Variables
  3. Go to the Server Components Tab
  4. Search for TransformCompoent and click on it
  5. Look for _localPosition (NOT LocalPosition), the first value is the x coordinate, and the second is the y value
  6. change it in .25 increments!

this can be done for ALL entities! seen usually in buttons/lockers
